# Roadmap: тема RMM для LuCI

## Отправная точка

Релиз `luci-v0.1.0` содержит два независимых пакета: `luci-theme-rmm` и
`luci-app-rmm-dashboard`. Тема наследует меню и форму входа LuCI Bootstrap,
импортирует его CSS и добавляет компактную тёмную палитру. Dashboard показывает
состояние роутера, WAN и локального RMM-агента, обновляя данные раз в 30 секунд.
Пакеты собираются для OpenWrt 24.10.7 (`.ipk`) и 25.12.4 (`.apk`) и попадают
в общий подписанный feed RMM.

Цель — довести тему до полноценной оболочки LuCI в стиле `DESIGN.md`, сохранив
совместимость со штатными страницами и сторонними пакетами. Dashboard остаётся
отдельным пакетом и работает также со штатной темой. Тема не меняет сеть,
настройки роутера и активную тему при установке.

## P0 — зафиксировать базу и проверить на устройствах

- Составить матрицу страниц LuCI для ручной проверки: вход, обзор, сеть,
  Wi-Fi, firewall, DHCP, сервисы, системные настройки, таблицы, формы,
  модальные окна, ошибки и страницы сторонних пакетов.
- Проверить оба формата пакетов на OpenWrt 24.10 и 25.12; проверить установку,
  обновление, удаление и возврат на Bootstrap по SSH.
- Снять скриншоты на ширинах 320, 390, 768, 1024 и 1440 px, при 200% zoom;
  записать дефекты в короткий чеклист с указанием страницы и ширины.
- Проверить dashboard отдельно с запущенным, остановленным и отсутствующим
  RMM-агентом, а также при отказе каждого ubus-запроса.

**Готово, когда:** есть воспроизводимый список дефектов и подтверждённый
безопасный откат к Bootstrap для обеих поддерживаемых версий OpenWrt.

## P1 — оболочка и навигация RMM

- Выделить токены `DESIGN.md` в один слой CSS и убрать повторяющиеся значения
из темы и dashboard.
- Сделать боковую навигацию на desktop и компактную нижнюю навигацию с доступом
ко всем разделам на mobile; сохранить штатную структуру меню, ссылки,
права доступа и обработчики LuCI.
- Привести шапку, хлебные крошки, заголовки, индикаторы и футер к единой
иерархии; обеспечить длинные имена устройств, перевод и 200% zoom.
- Проверить клавиатуру, видимый фокус, активный пункт, открытие вложенных
разделов и отсутствие горизонтального скролла страницы от 320 px.

**Готово, когда:** все существующие пункты LuCI доступны мышью, касанием и
клавиатурой; оболочка соответствует разделам Navigation и Responsive system
в `DESIGN.md` без изменения маршрутов LuCI.

## P2 — покрытие штатных компонентов LuCI

- Привести к токенам формы CBI, select/dropdown, вкладки, таблицы, уведомления,
  диалоги, кнопки и состояния disabled/focus/error/success.
- Проверить длинные IPv6, MAC, пути, логи и вывод команд; ограничить переполнение
внутри компонента вместо горизонтального скролла всей страницы.
- Проверить сторонние страницы на типовых классах LuCI. Исправлять правила
компонентов, не наращивая цепочку частных CSS-переопределений.
- Проверить контраст и состояния без опоры только на цвет; использовать Tabler
Icons для новых иконок согласно `DESIGN.md`.

**Готово, когда:** страницы из матрицы P0 читаемы и управляемы на mobile и
desktop, а тема не ломает штатные формы и предупреждения LuCI.

## P3 — dashboard как рабочий обзор роутера

- Разделить данные на «Система», «Сеть» и «RMM-агент» без декоративных карточек;
  показывать время последнего успешного обновления и состояния loading, stale,
  unavailable и access denied.
- Уточнить семантику WAN: состояние интерфейса не считать проверкой доступа
в Интернет. Добавлять интернет-проверку только как отдельный показатель из
доступного источника, не учащая агентский ping и не меняя heartbeat 30 секунд.
- Добавить полезные показатели по мере подтверждения источников: использование
памяти, аптайм, интерфейсы и трафик, температура при наличии датчика,
  состояние сервиса RMM. Для каждого значения указать источник и единицу.
- Ограничить RPC/ACL чтением необходимых данных; не добавлять команды изменения
конфигурации в обзор. Обновление страницы остаётся 30 секунд, а ошибки одного
источника не скрывают остальные секции.

**Готово, когда:** обзор показывает достоверные данные и понятные частичные
ошибки с установленным и отсутствующим агентом, в теме RMM и Bootstrap.

## P4 — поиск и настройки темы после стабилизации оболочки

- Взять из Proton2025 идеи поиска по страницам и настройкам LuCI, но определить
отдельную реализацию для RMM: сначала локальный поиск по доступному меню,
  затем при необходимости индекс настроек с ограниченными RPC-правами.
- Поиск должен учитывать права пользователя, поддерживать клавиатуру и
  корректно работать с русскими и английскими названиями. Кэш не должен
  раскрывать недоступные страницы.
- Настройки темы вводить только при подтверждённой потребности. Начать с
  системного dark/light режима и сохранить безопасный дефолт; отказаться от
  декоративных эффектов, противоречащих `DESIGN.md`.
- Не переносить экспериментальную SPA-навигацию, обновление пакета из UI и
  отдельные административные RPC-модули без самостоятельного обоснования и
  проверки безопасности.

**Готово, когда:** поиск открывает только доступные страницы, не мешает
навигации LuCI и не требует лишних прав; настройки переживают обновление пакета.

## P5 — качество релиза

- Автоматизировать проверку JS/JSON, упаковки файлов, зависимостей и двух SDK
  сборок; добавить осмысленные проверки для логики dashboard и поиска.
- Перед релизом повторить матрицу P0 на OpenWrt 24.10/25.12, включая обновление
  с `0.1.0`, удаление и откат на Bootstrap.
- Обновить README, скриншоты, changelog и инструкции установки из общего feed.
  Публиковать подписанный тег и проверять наличие обоих пакетов в GitHub Release
  и общем feed.

**Готово, когда:** выпуск воспроизводим, проверен на обеих ветках OpenWrt и
имеет работающий путь отката.

## Порядок работы

Сначала P0 → P1 → P2: это основа темы. P3 можно вести после фиксации токенов
и оболочки. P4 — отдельный этап после проверки совместимости, а P5 выполняется
на каждом релизном срезе. Proton2025 используется как функциональный ориентир;
при заимствовании кода нужно сохранить его лицензию и атрибуцию.

## Срез 0.3.0 — P2

Реализованы локальная прокрутка таблиц/вывода, подписанные мобильные строки,
вертикальная диагностика, размеры контролов, вкладки, dropdown, состояния
форм и диалоги. Добавлены DOM-проверки обновления строк, сохранения полей,
фокуса, геометрии dropdown и стартовой подсветки; тестовый DOM не входит в пакеты.
Проверка на роутере пока относится к 0.2.0; перед закрытием P2 остаются новый
пакет на устройствах, физический телефон, 200% zoom, OpenWrt 24.10 и сторонние
диалоги. Следующий функциональный этап — P3.
