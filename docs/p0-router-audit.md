# P0: аудит LuCI на действующем роутере

Дата: 2026-09-28–29. Проверка выполнялась только через открытые страницы LuCI:
без сохранения форм, установки/удаления пакетов, перезагрузки и изменения
настроек роутера. Адреса, MAC, SSID, имена клиентов и содержимое журналов в
отчёт не включены. Анализ страницы входа — в `docs/p0-login-audit.md`.

## Проверенная база

- Устройство: Cudy WR3000S v1, OpenWrt 25.12.5, LuCI 26.180.
- Установлены `luci-theme-rmm` и `luci-app-rmm-dashboard` версии `0.1.0-r1`.
  Версии прочитаны во вкладке «Установлено» пакетного менеджера; выполнялась
  только фильтрация списка.
- Проверен один браузер и один действующий роутер. Ветки OpenWrt 24.10 здесь нет.

## Адаптивность основных страниц

Для каждой страницы после загрузки измерена ширина документа
`document.documentElement.scrollWidth` на viewport высотой 800 px. Видимая
ширина (`clientWidth`) может быть на 15 px меньше viewport из-за вертикального
скроллбара; значение больше viewport означает явное переполнение. Значения в
таблице указаны в пикселях. Это снимок состояния: количество клиентов и строки
таблиц меняются, поэтому измеренная ширина может вырасти. При повторной
проверке обзора на 390 px она выросла с 603 до 742 px.

| Страница | 320 | 390 | 768 | 1024 | 1440 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Статус → Обзор | **603** | **603** | 753 | 1009 | 1425 |
| Статус → RMM overview | 320 | 375 | 753 | 1009 | 1425 |
| Сеть → Интерфейсы | **686** | **686** | 753 | 1009 | 1425 |
| Сеть → Беспроводная сеть | **546** | **546** | 753 | 1009 | 1425 |
| Сеть → Межсетевой экран | **834** | **834** | **834** | 1009 | 1425 |
| Сеть → DHCP | **1083** | **1083** | **1083** | **1095** | 1425 |
| Система → Система | **328** | 375 | 753 | 1009 | 1425 |
| Службы → RMM Агент | 320 | 375 | 753 | 1009 | 1425 |
| Службы → NetShift | 320 | 375 | 753 | 1009 | 1425 |
| Статус → Системный журнал | 320 | 375 | 753 | 1009 | 1425 |

Даже при ширине документа 320 px на viewport 320 px может оставаться
15-пиксельный горизонтальный скролл: из-за вертикального скроллбара видимая
область равна 305 px. Это наблюдалось на RMM dashboard. В теме есть правило
`html, body { min-width: 320px; }`.

Дополнительная проверка при 390 px: маршрутизация в статусе — документ 1003 px;
процессы — 893 px; маршруты сети — 485 px; менеджер пакетов — 953 px; DDNS —
999 px. На страницах статуса firewall, realtime, WireGuard, а также DNS,
NetShift и Zapret широкого переполнения при 390 px не обнаружено. Страница
анализа каналов запускает сканирование Wi-Fi при открытии; её итоговая
раскладка не оценивалась.

## Находки по приоритету

### R1 — таблицы растягивают всю страницу (высокий)

В таблицах аренды DHCP на обзоре, интерфейсов, Wi-Fi, firewall, DHCP,
маршрутов, процессов, пакетов и DDNS ширина содержимого выходит за viewport.
Например, таблица DHCP имеет ширину документа 1083 px даже при viewport 768 px.
Горизонтально прокручивается вся страница, включая навигацию. Источники:
`#status_leases`, `.table.cbi-section-table` и `#packages`. Требуется
локальное горизонтальное прокручивание таблиц либо мобильное представление
строк с метками; страница целиком не должна переполняться.

### R2 — мобильная навигация занимает много места и обрезает хост (высокий)

На dashboard высота шапки 161 px при 320 px и 121 px при 390 px, тогда как
при 768 px и шире — 48 px. Видимая ширина ссылки с названием роутера — 64 и
79 px соответственно при содержимом 145 px; название обрезано. Пункты меню
разбиваются на несколько строк. Оболочка пока сохраняет верхнее меню Bootstrap
и не соответствует мобильной навигации из `DESIGN.md`.

### R3 — минимальная ширина и отдельные элементы формы (средний)

На 320 px страница «Система» достигает 328 px из-за блока `.cbi-value-field`
с управлением системным временем. Правило `min-width: 320px` также даёт
15-пиксельное переполнение на страницах с вертикальным скроллбаром. Проверять
нужно по `clientWidth`, а не только по `innerWidth`.

### R4 — dashboard смешивает русский и английский (средний)

При `lang="ru"` заголовок `RMM overview`, секции `Router` и `WAN connection`,
подписи `Firmware`, `Memory total`, `Heartbeat interval` и сообщение об
обновлении остаются английскими. Пакету нужны переводы LuCI и проверка
локализации. Данные dashboard загружаются; отдельно показаны heartbeat 30 s
и интервал проверки связности 600 s.

## Что подтвердилось и что осталось

- Dashboard работает как отдельная страница и при 390–1440 px не расширяет
  документ сверх видимой области. При 320 px остаётся общий 15-пиксельный
  дефект минимальной ширины.
- Страницы агента, NetShift и системного журнала загрузились; на 390–1440 px
  значительного горизонтального переполнения не выявлено.
- Не проверялись изменения настроек, сохранение форм, установка/обновление/
  удаление пакетов, перезагрузка, поведение модальных подтверждений и откат
  темы: эти действия нарушили бы режим аудита только на чтение.
- Масштаб браузера 200% и второй физический роутер с OpenWrt 24.10 остаются
  отдельными пунктами P0.

Следующий безопасный шаг — исправлять R1–R4 в коде темы и dashboard, затем
повторить измерения на этих же маршрутах и ширинах. Изменять настройки
действующего роутера для проверки CSS не требуется.
