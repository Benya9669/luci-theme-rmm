# P0: анализ страницы входа LuCI

Дата: 2026-09-28. Проверенный адрес: `http://10.10.10.1/cgi-bin/luci/`.
На роутере активна тема `/luci-static/rmm`; CSS темы и Bootstrap доступны.
Проверка выполнена без отправки учётных данных и без изменения настроек роутера.
Точная версия установленного пакета на роутере пока не подтверждена.

## Что проверено

| Проверка | Результат |
| --- | --- |
| Загрузка формы | Страница открывается, поля и кнопка видны. |
| Доступные названия | Поля распознаются как «Имя пользователя» и «Пароль», кнопка — «Войти». |
| Порядок клавиатуры | Имя пользователя → пароль → кнопка входа. |
| Фокус | Видимая обводка есть у полей и кнопки. |
| Автозаполнение | В шаблоне указаны `autocomplete="username"` и `autocomplete="current-password"`; работа менеджера паролей не проверялась. |
| Адаптивная ширина | Проверены viewport 320, 390, 768, 1024 и 1440 px при высоте 800 px. Горизонтального переполнения документа нет. |

| 390 px | 390 px | 351 px | 210 px | Подписи над полями. |
| 768 px | 768 px | 600 px | 210 px | Подписи слева от полей. |

Карточка остаётся по центру и целиком внутри viewport. На 320 и 390 px
кнопка занимает доступную ширину; поля остаются фиксированными по 210 px.
На 768 px и шире карточка ограничена 600 px. Раскладка переключается между
390 и 768 px, без видимого наложения элементов.

## Найденные проблемы

### L1 — форма использует лишь половину внутренней панели (P1, UI)

Поля сохраняют фиксированную ширину 210 px на всех пяти проверенных размерах.
При 390 px форма имеет ширину 321 px, а при 768 px — 570 px, поэтому
пространство справа используется неравномерно; кнопка занимает ширину формы.
Вероятный источник — штатная раскладка `bootstrap.sysauth`, на которую
тема добавляет лишь общие правила CSS. Нужен ограниченный стилевой слой для
формы входа: согласованные ширины подписи/поля/кнопки и внутренние отступы
без изменения механизма авторизации.

### L2 — нет идентичности RMM на входе (P2, UI)

Виден общий заголовок «Веб-интерфейс» без имени RMM или хоста. На странице
входа шапка темы скрыта, поскольку используется `blank_page`. Стоит добавить
компактную идентичность продукта и роутера в пределах одной формы, сохранив
штатные предупреждения и сообщения об ошибке LuCI.

### L3 — страница открыта по HTTP (окружение/безопасность)

Адрес не использует TLS. Ввод пароля в такую форму передаёт его без защиты
транспортного канала. Это настройка веб-доступа роутера, а не дефект CSS темы.
Перед полноценной проверкой входа следует использовать настроенный HTTPS
или другой доверенный защищённый способ доступа. Тема не должна скрывать
штатные предупреждения браузера.

## Что ещё нужно проверить для P0

- Настоящий браузерный масштаб 200%: in-app browser не изменил zoom через
  клавиатурную комбинацию, поэтому этот пункт остаётся непроверенным.
- Состояния неверного пароля, дополнительной аутентификации, отправки формы
  и фокуса после ошибки — на тестовом или защищённом сеансе.
- Сохранность штатных предупреждений LuCI: пустой пароль root и initramfs.
- Совместимость с менеджером паролей и экранным диктором.
- Точную версию пакета на роутере и откат на Bootstrap через SSH.

Кодовые точки для исправления: `packages/luci-theme-rmm/ucode/template/themes/rmm/sysauth.ut`,
`packages/luci-theme-rmm/htdocs/luci-static/rmm/cascade.css`. Правила страницы
входа из `DESIGN.md` требуют компактной формы, связанных ошибок и предсказуемого
порядка фокуса.
